# 도메인은 불러오기만 해서 일어나는 일이 없다

## 결정

- `packages/domain/package.json`에 `"sideEffects": false`를 둔다. 번들러는 이것을 보고, 배럴(`export *`)이 넘긴 것 중 쓰지 않는
  모듈을 버리고 쓰는 화면의 조각으로 보낸다.
- 그 전제를 lint가 지킨다(`noTopLevelEffects`, 허용 목록):
  - 모듈 최상위 문장은 import·export와 변수·함수·타입 선언, 타입만인 `declare global`·`declare module`뿐이다.
  - 클래스는 쓰지 않는다(선언·식 모두 — static 블록이 불러올 때 돈다). enum도 내보내지 않는다(불러올 때 객체를 만든다).
  - 기본 내보내기는 함수 선언이나 이미 선언한 이름뿐이고, 상수의 초기값을 즉시 실행 함수로 만들지 않는다.
  - 가드 테스트가 위반마다 막히는지와 선언이 통과하는지(양성 대조)를 본다.
- lint가 못 보는 것: 상수의 초기값 안에서 부르는 함수가 값을 만들기만 하는지(전역을 바꾸거나 어딘가에 등록하지 않는지). 이것은
  규칙으로만 남기고 리뷰에서 본다.

## 이유

배럴 하나로 들어오는 도메인은 편하지만, 번들러가 부작용이 있을지 모른다고 보면 배럴을 부르는 첫 화면이 모든 모듈을 끌어온다.
한 화면만 쓰는 계산까지 첫 로드에 실린다. 부작용이 없다고 알리면 번들러가 사용처를 따라 나눈다. 대신 그 말이 거짓이 되면
불러올 때 하던 일(등록·전역 설정)이 운영 빌드에서만 조용히 빠지므로, 최상위를 선언만으로 묶어 거짓이 될 길을 막는다.
이 템플릿에는 번들되는 앱이 없어 크기 이득은 재지 않았다.
