# 계층 구조(DDD + 클린 아키텍처)를 문서가 아니라 lint로 강제한다

## 결정

- 의존은 바깥 → 안쪽으로만: `domain` ← `application`(유스케이스·포트) ← `infrastructure`(어댑터)·`interface`(HTTP) ← `main`(조립).
  프레임워크·드라이버는 바깥 레이어에만 둔다.
- 경계는 eslint-plugin-boundaries로 **허용 목록만** 적는다(기본 금지). 로컬 레이어·워크스페이스 패키지·npm 모듈·Node 코어
  모듈을 모두 검사한다. 새 폴더·패키지는 `layers()`에 적어야 열린다.
- 도메인 모듈은 공개 API(`index.ts`)로만 들어온다.
- DDD는 비례적으로 — 모듈·엔티티·순수 규칙까지만. 이벤트 버스·애그리거트 클래스 같은 의식은 두지 않는다.
- 도메인의 유일한 외부 의존은 zod다(엔티티 검증의 단일 출처이고 I/O가 아니다).
- 설정이 실제로 막는지는 `packages/eslint-config/guards.test.mts`가 위반을 넣어 확인한다(양성 대조 포함).

## 이유

문서에 적은 규칙은 사람도 에이전트도 잊는다. lint·테스트는 잊지 않는다. 규칙을 지우거나 풀면 가드 테스트가 실패하므로
"설정에 적혀 있다"가 아니라 "위반하면 막힌다"가 늘 증명된다.
