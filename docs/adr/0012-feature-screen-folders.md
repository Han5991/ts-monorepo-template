# 화면 앱의 기능 폴더는 화면 단위 하위 폴더로 나누고, 둘 이상의 화면이 쓰는 것은 common에 둔다

## 결정

템플릿에는 UI 앱이 없다(ADR 0005). 화면 앱(`apps/web` 등)을 더할 때 따른다. 아직 lint가 막지 않는다 — 앱을 더하면 경계
(`app` → `features` → 공용 `ui`·`@app/domain`, 기능끼리 import 금지)를 `layers()`에 적어 강제한다.

- 기능(`features/<기능>`) 안은 페이지·보기·시트마다 폴더 하나(`list/`·`detail/`·`sheet/`)로 나눈다. 라우트·시트와 1:1이다.
- 둘 이상의 화면이 쓰는 것은 `common/`에 둔다. 한 화면의 모양을 따라 하는 것(그 화면의 로딩 뼈대)은 그 화면 폴더에 둔다.
- 하위 폴더는 찾기 쉬우라고 나눈 것이고 경계가 아니다 — 기능 안은 한 레이어다.
- 역할별 폴더(`hooks/`·`lib/`·`utils/`)로 나누지 않는다. 역할은 파일 접미사가 말한다(ADR 0015).

## 이유

기능 폴더가 평평하면 페이지와 시트, 그 폼·문구 파일이 수십 개 섞여 "이 화면의 코드는 어디인가"에 답하기 어렵다. 화면 단위
폴더는 라우트·시트와 1:1이라 바로 찾아간다. 역할별 폴더는 "무엇으로 만들었나"만 말해 계산을 숨기고 한 흐름을 여러 폴더로 찢는다.
