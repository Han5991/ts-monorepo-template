# API는 계약 우선, 경로는 /api/v1

## 결정

- 엔드포인트의 경로·파라미터·응답은 `packages/contracts` 한 곳에 있고, 서버(라우트 등록·파라미터 검증)와
  클라이언트(경로 조립·응답 검증)가 같은 정의를 쓴다. 계약의 모든 엔드포인트에 핸들러가 없으면 서버가 컴파일되지 않는다.
- 웹과 API가 같은 오리진을 쓰도록 `/api` 접두. 클라이언트가 따로 배포될 수 있어 `/api/v1` 버전 접두. 인프라용
  `/api/health`만 무버전. 경로 규칙은 계약 테스트가 강제한다.
- 파라미터 중 경로에 `:이름`으로 있는 것은 경로로, 나머지는 쿼리 문자열로 간다(값이 없는 키는 보내지 않는다).
  서버는 쿼리와 경로 값을 합쳐 같은 스키마로 검증한다(경로 값이 이긴다).
- API 계약(DTO)은 도메인과 따로 두고 경계에서 옮겨 담는다. 예외: 상태 같은 enum 값은 도메인 상수를 계약이 그대로
  가져다 쓴다 — 단일 출처가 더 중요하다.
